## 二、六大核心技术模式

### 1. Prompt Engineering（提示工程）

**一句话定义**：通过精心设计的提示词，让 LLM 输出想要的结果

**核心思想**：
```
用户输入 + 提示词模板 → LLM → 输出
```

**适用场景**：
- 简单问答、翻译、摘要
- 内容生成（文案、代码片段）
- 格式化输出

**优点**：
- ✅ 实现最简单，无需代码
- ✅ 成本最低
- ✅ 快速验证想法

**缺点**：
- ❌ 无法获取外部信息
- ❌ 无法执行实际操作
- ❌ 上下文窗口有限

**典型实现**：
```python
# Few-shot Prompting
prompt = """
你是一个数据分析专家。

示例：
输入：销售额数据 [100, 150, 200]
输出：平均值为 150，呈上升趋势

现在分析：{user_input}
"""
```

### 2. RAG（检索增强生成）

**一句话定义**：先从知识库检索相关信息，再让 LLM 基于检索结果生成答案

**核心思想**：
```
用户问题 → 向量检索 → 获取相关文档 → LLM + 文档 → 生成答案
```

**架构图**：
```
┌─────────────────────────────────────────────────────┐
│                     RAG 架构                         │
├─────────────────────────────────────────────────────┤
│                                                     │
│  离线流程（建索引）                                   │
│  ┌─────┐    ┌─────┐    ┌─────┐                    │
│  │文档 │ → │切分 │ → │向量化│ → 向量数据库          │
│  └─────┘    └─────┘    └─────┘                    │
│                                                     │
│  在线流程（检索回答）                                 │
│  ┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐        │
│  │问题 │ → │向量化│ → │检索 │ → │LLM  │ → 答案    │
│  └─────┘    └─────┘    └─────┘    └─────┘        │
│                          ↑                         │
│                    向量数据库                        │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**适用场景**：
- 企业知识库问答
- 文档检索分析
- 客服机器人
- 法律、医疗等专业领域问答

**优点**：
- ✅ 可获取外部知识，突破上下文限制
- ✅ 答案可追溯（有引用来源）
- ✅ 知识更新只需更新文档库
- ✅ 无需微调，成本较低

**缺点**：
- ❌ 需要构建向量数据库
- ❌ 检索质量影响最终效果
- ❌ 无法执行实际操作

**典型技术栈**：
- 向量数据库：Milvus、Pinecone、Chroma、FAISS
- Embedding：OpenAI embeddings、BGE、M3E
- RAG 框架：LangChain、LlamaIndex

### 3. Function Calling / Tool Use（工具调用）

**一句话定义**：让 LLM 能够调用外部函数/工具，获取实时信息或执行操作

**核心思想**：
```
LLM 决定调用哪个函数 → 执行函数 → 返回结果给 LLM → 生成最终回答
```

**架构图**：
```
┌─────────────────────────────────────────────────────┐
│                  Function Calling                    │
├─────────────────────────────────────────────────────┤
│                                                     │
│  用户问题："今天北京天气怎么样？"                      │
│       │                                             │
│       ▼                                             │
│  ┌─────────┐                                       │
│  │   LLM   │ 判断：需要调用 get_weather 函数         │
│  └────┬────┘                                       │
│       │ 调用 get_weather("北京")                    │
│       ▼                                             │
│  ┌─────────┐                                       │
│  │ 函数执行 │ → 返回 {"temp": 25, "weather": "晴"}   │
│  └────┬────┘                                       │
│       │ 结果返回给 LLM                              │
│       ▼                                             │
│  ┌─────────┐                                       │
│  │   LLM   │ 生成："北京今天天气晴朗，气温 25°C"      │
│  └─────────┘                                       │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**适用场景**：
- 查询实时信息（天气、股价、新闻）
- 执行操作（发送邮件、创建订单）
- 调用外部 API
- 数据库查询

**优点**：
- ✅ 可获取实时信息
- ✅ 可执行实际操作
- ✅ 扩展 LLM 能力边界

**缺点**：
- ❌ 需要预定义函数
- ❌ 单次调用，无复杂规划
- ❌ 依赖 LLM 的函数选择能力

**典型实现**：
```python
# OpenAI Function Calling
functions = [
    {
        "name": "get_weather",
        "description": "获取城市天气",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string"}
            }
        }
    }
]

response = client.chat.completions.create(
    model="gpt-4",
    messages=[{"role": "user", "content": "北京天气"}],
    functions=functions
)
```

### 4. Agent（智能代理）

**一句话定义**：让 LLM 自主规划、决策、执行，完成复杂任务

**核心思想**：
```
目标 → LLM 思考 → 选择工具 → 执行 → 观察结果 → 再思考 → 循环直到完成
```

**架构图**：
```
┌─────────────────────────────────────────────────────┐
│                    Agent 架构                        │
├─────────────────────────────────────────────────────┤
│                                                     │
│               ┌─────────────┐                       │
│               │   目标/问题  │                       │
│               └──────┬──────┘                       │
│                      │                              │
│                      ▼                              │
│  ┌─────────────────────────────────────────────┐   │
│  │              ReAct 循环                       │   │
│  │                                             │   │
│  │   思考 ──→ 行动 ──→ 观察 ──→ 完成？           │   │
│  │    ↑                      │                  │   │
│  │    └──────────────────────┘                  │   │
│  │                  否                           │   │
│  └─────────────────────────────────────────────┘   │
│                      │                              │
│                      ▼                              │
│               ┌─────────────┐                       │
│               │   最终结果   │                       │
│               └─────────────┘                       │
│                                                     │
│  核心组件：                                          │
│  • Planner（规划器）：分解任务、制定计划              │
│  • Tool Registry（工具库）：可调用的工具集合          │
│  • Executor（执行器）：执行具体操作                  │
│  • Memory（记忆）：保存上下文和历史                  │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**适用场景**：
- 复杂数据分析
- 自动化工作流
- 研究调研
- 代码生成和调试
- 需要多步骤推理的任务

**优点**：
- ✅ 可完成复杂任务
- ✅ 自主规划和调整
- ✅ 高度灵活

**缺点**：
- ❌ 开发复杂度高
- ❌ 执行成本较高
- ❌ 可能陷入循环
- ❌ 需要 guardrails（安全护栏）

**典型框架**：
- LangChain Agent
- AutoGPT
- CrewAI
- OpenAI Assistants API
- **Simple BI Agent** ← 你的项目！

### 5. Multi-Agent（多代理协作）

**一句话定义**：多个 Agent 分工协作，共同完成复杂任务

**核心思想**：
```
协调器接收任务 → 分解为子任务 → 分配给专业 Agent → 协作执行 → 聚合结果
```

**架构图**：
```
┌─────────────────────────────────────────────────────┐
│                 Multi-Agent 架构                     │
├─────────────────────────────────────────────────────┤
│                                                     │
│               ┌─────────────┐                       │
│               │ Coordinator │ ← 协调器              │
│               │   协调器    │                       │
│               └──────┬──────┘                       │
│                      │ 分配任务                      │
│        ┌─────────────┼─────────────┐               │
│        │             │             │               │
│        ▼             ▼             ▼               │
│   ┌─────────┐  ┌─────────┐  ┌─────────┐           │
│   │ Agent A │  │ Agent B │  │ Agent C │           │
│   │ 研究员  │  │ 程序员  │  │ 审核员  │           │
│   └─────────┘  └─────────┘  └─────────┘           │
│        │             │             │               │
│        └─────────────┴─────────────┘               │
│                      │                              │
│                      ▼                              │
│               ┌─────────────┐                       │
│               │   聚合结果   │                       │
│               └─────────────┘                       │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**适用场景**：
- 软件开发（需求→设计→编码→测试）
- 复杂研究任务
- 内容创作团队
- 决策支持系统

**优点**：
- ✅ 专业分工，各司其职
- ✅ 可并行执行
- ✅ 更好的可维护性

**缺点**：
- ❌ 架构复杂
- ❌ Agent 间通信开销
- ❌ 调试困难

**典型框架**：
- CrewAI
- AutoGen
- LangGraph
- MetaGPT

### 6. Workflow / Pipeline（工作流编排）

**一句话定义**：预定义好执行步骤，LLM 按流程执行

**核心思想**：
```
预定义步骤序列 → 按顺序执行 → 输出结果
```

**架构图**：
```
┌─────────────────────────────────────────────────────┐
│                  Workflow 架构                       │
├─────────────────────────────────────────────────────┤
│                                                     │
│  Step 1       Step 2       Step 3       Step 4     │
│  ┌─────┐      ┌─────┐      ┌─────┐      ┌─────┐   │
│  │数据 │ ───→ │分析 │ ───→ │可视化│ ───→ │报告 │   │
│  │获取 │      │处理 │      │生成 │      │输出 │   │
│  └─────┘      └─────┘      └─────┘      └─────┘   │
│                                                     │
│  特点：                                              │
│  • 步骤固定，可预测                                   │
│  • 可视化流程                                        │
│  • 易于调试和维护                                     │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**适用场景**：
- 标准化业务流程
- 数据处理管道
- 自动化报告生成

**优点**：
- ✅ 流程可预测
- ✅ 易于监控和调试
- ✅ 执行效率高

**缺点**：
- ❌ 灵活性低
- ❌ 无法动态调整

**典型框架**：
- LangGraph
- Dify
- Flowise
- n8n

## 四、组合使用模式

实际项目中，往往是多种技术组合使用：

### 组合 1：RAG + Function Calling
```
用户问题 → RAG 检索知识库 → Function Calling 获取实时数据 → LLM 生成答案
```
**例子**：智能客服（知识库 + 查询订单状态）

### 组合 2：Agent + RAG
```
Agent 自主规划 → 调用 RAG 获取信息 → 分析推理 → 生成结果
```
**例子**：研究助理 Agent

### 组合 3：Multi-Agent + Workflow
```
Workflow 定义流程 → 每个 Agent 负责一个环节 → 协作完成
```
**例子**：自动化报告生成系统
