# 进度反馈机制设计

> Claude Code 应用报告 - P0 优先级实施

---

## 设计目标

1. **超过 5 分钟的任务** → 自动更新 PROGRESS.md
2. **用户随时可查** → 标准化的进度文件格式
3. **卡住自动上报** → 超过 2 分钟无进展通知用户

---

## 实现方案

### 方案一：Agent 自律（推荐）

**原理**：Agent 在执行长任务时，自己更新进度文件

**规范**：

```markdown
# PROGRESS.md 模板

# 当前任务进度

> 最后更新：YYYY-MM-DD HH:MM

## 状态

**当前**：正在执行的任务
**状态**：进行中 / 等待 / 完成

## 进度

- [x] 已完成的步骤 1
- [x] 已完成的步骤 2
- [ ] 正在执行的步骤 3
- [ ] 待执行的步骤 4

## 预计完成时间

约 X 分钟

## 备注

（可选：当前卡点、需要的帮助等）
```

**Agent 行为规范**：
1. 开始任务 → 创建 PROGRESS.md
2. 每完成一步 → 更新 PROGRESS.md
3. 任务完成 → 删除或标记完成

---

### 方案二：Heartbeat 自动检查

**原理**：利用 OpenClaw 的 heartbeat 机制，定期检查进度

**配置**：

```json
{
  "agents": {
    "defaults": {
      "heartbeat": {
        "every": "5m",
        "prompt": "检查 PROGRESS.md，如果超过 5 分钟没更新，通知用户"
      }
    }
  }
}
```

---

### 方案三：Sub-agent 进度汇报

**原理**：子 Agent 完成后自动向父 Agent 汇报

**实现**：
- `sessions_spawn` 的子 Agent 完成后，发送完成事件
- 父 Agent 收到事件后，更新进度


## 立即可用

**用户可执行的命令**：

```bash
# 查看当前进度
cat PROGRESS.md

# 查看所有进行中的任务
find . -name "PROGRESS.md" -exec cat {} \;
```
