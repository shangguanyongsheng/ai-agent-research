## 知识点 1：写好 Prompt 的公式

### 第一步：概念解释（简单语言）

好的 Prompt = 清晰的目标 + 足够的上下文 + 明确的约束 + 验证标准。

### 第二步：类比理解（生活例子）

就像给厨师下订单——不能只说"做个菜"，要说"做个不辣的宫保鸡丁，不要花生，三个人份，半小时内完成"。

### 第三步：代码实践（动手实验）

**❌ 模糊的 Prompt**：
```text
> 修复这个 bug
```

**✅ 具体的 Prompt**：
```text
> 用户报告登录失败后没有显示错误提示。
> 
> 目标：修复错误提示显示问题
> 
> 上下文：
> - 相关文件：src/auth/login.tsx
> - 当前行为：登录失败后页面无反应
> - 期望行为：显示红色错误提示，持续 3 秒
> 
> 约束：
> - 使用现有的 toast 组件
> - 不要修改 API 调用逻辑
> 
> 验证：
> - 模拟登录失败，确认提示显示
> - 确认提示 3 秒后消失
```

**Prompt 公式模板**：
```text
目标：我想要达到什么效果

上下文：
- 相关文件/代码
- 现有架构/风格

约束：
- 不能做什么
- 必须遵循什么

验证：
- 如何确认任务完成
```

### 第四步：知识关联

- 提供上下文可以减少 Claude 的猜测
- 明确约束可以避免不必要的修改
- 验证标准确保结果符合预期

## 知识点 2：CLAUDE.md 编写原则

### 第一步：概念解释（简单语言）

CLAUDE.md 是项目的"说明书"——告诉 Claude 你的项目结构、构建命令、代码风格、注意事项。

### 第二步：类比理解（生活例子）

就像给新同事一份"入职指南"——告诉他项目怎么构建、代码怎么写、哪些坑要避开。

### 第三步：代码实践（动手实验）

**CLAUDE.md 模板**：
```markdown
# 项目名称

## 构建命令
- 开发：`npm run dev`
- 构建：`npm run build`
- 测试：`npm test`

## 代码风格
- 使用 2 空格缩进
- 组件使用 PascalCase
- 函数使用 camelCase
- 优先使用 TypeScript 类型

## 架构约定
- API 路由：src/app/api/
- 组件：src/components/
- 工具函数：src/lib/

## 注意事项
- 不要修改 src/generated/ 目录
- 环境变量在 .env.local
- 提交前运行 npm run lint
```

**重要原则**：

| 原则 | 说明 |
|------|------|
| **简洁** | 控制在 200 行以内 |
| **具体** | 用具体命令，不要用模糊描述 |
| **结构化** | 使用标题、列表、表格 |
| **无冲突** | 定期删除过时规则 |

### 第四步：知识关联

- CLAUDE.md 放在项目根目录
- 可以用 `.claude/rules/` 拆分详细规则
- Claude 会在每次会话开始时读取

## 知识点 3：管理上下文

### 第一步：概念解释（简单语言）

上下文是 Claude 能"看到"的信息。上下文太多会降低效率，上下文太少会导致错误判断。

### 第二步：类比理解（生活例子）

就像开会——信息太多记不住，信息太少做不了决定。需要适时总结和清理。

### 第三步：代码实践（动手实验）

**查看上下文使用**：
```bash
claude /context
```

**压缩上下文**：
```text
> /compact 保留关键信息，重点是 API 设计
```

**清除开始新任务**：
```text
> /clear
```

**上下文管理技巧**：

| 情况 | 处理方式 |
|------|----------|
| 会话过长 | `/compact` 压缩 |
| 切换新任务 | `/clear` 清除 |
| 探索性任务 | 用 subagent 隔离 |
| 大文件读取 | 指定关键部分 |

### 第四步：知识关联

- 上下文窗口有限，要精打细算
- 重要信息放在 CLAUDE.md 开头
- `/compact` 可能丢失细节，重要信息要提前保存

## 知识点 4：权限管理

### 第一步：概念解释（简单语言）

权限决定 Claude 能自动做什么，需要你确认什么。合理的权限设置可以平衡效率和安全性。

### 第二步：类比理解（生活例子）

就像给助手设置权限——日常小事自己决定，重要事项必须请示。

### 第三步：代码实践（动手实验）

**三种权限模式**：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **Normal** | 重要操作需确认 | 日常工作（默认） |
| **Auto-Accept** | 大部分操作自动执行 | 紧急修复、可信任务 |
| **Plan** | 只读不写，先规划 | 复杂任务、代码审查 |

**切换权限模式**：
```bash
# 启动时指定
claude --permission-mode plan

# 会话中切换（Shift+Tab）
```

**管理权限列表**：
```bash
claude /permissions
```

### 第四步：知识关联

- 权限设置可以在 CLAUDE.md 中预定义
- 团队项目建议使用 Normal 模式
- 个人项目可以用 Auto-Accept 提升效率

## 知识点 5：常见工作流模式

### 第一步：概念解释（简单语言）

不同任务有不同的最佳处理模式。了解这些模式可以更高效地使用 Claude Code。

### 第二步：类比理解（生活例子）

就像不同的工作有不同的 SOP（标准操作程序）——写代码有写代码的流程，修 bug 有修 bug 的流程。

### 第三步：代码实践（动手实验）

**模式 1：修复 Bug**
```text
1. 描述问题现象（错误信息、预期行为）
2. 让 Claude 定位原因
3. 让 Claude 提出修复方案
4. 确认后执行修复
5. 运行测试验证
```

**模式 2：添加功能**
```text
1. 描述需求（用户故事）
2. 让 Claude 分析现有架构
3. 让 Claude 设计实现方案
4. 确认方案后实现
5. 添加测试
6. 更新文档
```

**模式 3：代码重构**
```text
1. 使用 Plan Mode 分析现状
2. 让 Claude 提出重构方案
3. 小步重构，每次验证
4. 确保测试通过
5. 提交并说明改动
```

**模式 4：代码审查**
```text
1. 使用 /init 让 Claude 理解项目
2. 指定要审查的文件或 PR
3. 让 Claude 分析并提供反馈
4. 根据反馈修改或解释
```

### 第四步：知识关联

- 复杂任务先 Plan 再执行
- 每步验证，避免大量回滚
- 保存关键决策到 CLAUDE.md

## 知识点 6：效率提升技巧

### 第一步：概念解释（简单语言）

一些小技巧可以让 Claude Code 更好地为你服务。

### 第二步：类比理解（生活例子）

就像键盘快捷键——学会之后效率翻倍。

### 第三步：代码实践（动手实验）

**技巧 1：使用 @ 引用文件**
```text
> 分析 @src/auth/login.tsx 的认证流程
```

**技巧 2：批量操作**
```text
> 将 src/components/ 下所有 .js 文件改为 .tsx
> 先预览，再执行
```

**技巧 3：保存常用命令为 Skills**
```bash
# 创建 Skill 后
/review-pr 123  # 一键审查 PR
/deploy-staging # 一键部署
```

**技巧 4：使用 Auto Memory**
```bash
claude /memory auto on
# Claude 会自动记住你的偏好和修正
```

**技巧 5：并行处理**
```text
> 使用 subagents 并行：
> 1. 分析前端性能
> 2. 分析后端性能
> 3. 分析数据库查询
```

### 第四步：知识关联

- 定期整理 CLAUDE.md 和 Skills
- 使用 Hooks 自动化重复操作
- 用 MCP 扩展 Claude 的能力边界
