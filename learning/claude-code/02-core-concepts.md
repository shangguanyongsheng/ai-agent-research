## 知识点 1：代理型编码（Agentic Coding）

### 第一步：概念解释（简单语言）

代理型编码意味着 Claude 不只是"回答问题"，而是"完成任务"。它能主动读取文件、执行命令、修改代码，像一个独立的程序员在工作。

### 第二步：类比理解（生活例子）

传统 AI 聊天工具像咨询顾问——你问问题，他给建议。
代理型编码像外包团队——你描述需求，他们自己查资料、写代码、测试，把成品交给你。

```
传统模式：问 → 答 → 你自己动手
代理模式：描述需求 → Claude 自己动手 → 交付成品
```

### 第三步：代码实践（动手实验）

**传统 AI 聊天（问 → 答）：**
```text
你：这段代码有什么问题？
AI：第 5 行变量名不规范，第 10 行缺少错误处理。
你：（自己修改）
```

**Claude Code 代理模式（描述 → 完成）：**
```text
你：修复 auth.ts 中的所有 lint 错误
Claude：（读取文件，分析错误，修改代码，运行测试）
Claude：修复完成，共修复 3 个 lint 错误
```

### 第四步：知识关联

- 代理型编码需要权限批准机制
- 与 Cursor/Copilot 的核心区别
- 见 [知识点 2：权限模式](#知识点-2权限模式) 理解批准流程

## 知识点 2：权限模式

### 第一步：概念解释（简单语言）

Claude Code 有三种权限模式：Normal（默认）、Auto-Accept（自动批准）、Plan（只规划不执行）。你可以根据任务类型切换。

### 第二步：类比理解（生活例子）

就像和助理的合作方式：

- **Normal 模式**：助理做重要决定前会问你"这个可以吗？"
- **Auto-Accept 模式**：助理全权处理，不问问题
- **Plan 模式**：助理只写计划书，等你批准后再动手

### 第三步：代码实践（动手实验）

**切换权限模式：**

```bash
# 启动时指定模式
claude --permission-mode plan    # Plan 模式
claude --permission-mode accept  # Auto-Accept 模式
```

**运行中切换：**
```
按 Shift+Tab 切换模式
```

**三种模式对比：**

| 模式 | 用途 | 批准流程 |
|------|------|----------|
| Normal | 日常开发 | 每次修改都请求批准 |
| Auto-Accept | 快速迭代 | 自动执行，不请求批准 |
| Plan | 规划阶段 | 只分析不执行，适合理解代码 |

### 第四步：知识关联

- Plan 模式适合探索大型项目
- Auto-Accept 模式适合信任 Claude 的场景
- 可以配置允许列表避免重复批准

## 知识点 3：CLAUDE.md 项目配置

### 第一步：概念解释（简单语言）

CLAUDE.md 是一个配置文件，放在项目根目录。Claude 每次启动时都会读取它，知道项目怎么构建、怎么测试、有什么规范。

### 第二步：类比理解（生活例子）

就像给新员工发了一份入职手册——里面有办公规则、常用工具位置、工作流程。Claude 启动时自动读取这份手册。

### 第三步：代码实践（动手实验）

**创建 CLAUDE.md：**

```bash
# 自动生成
claude /init
```

**手动编写示例：**

```markdown
# 项目名称

## 构建命令
- 开发：`npm run dev`
- 构建：`npm run build`
- 测试：`npm test`

## 代码风格
- 使用 TypeScript，不用 JavaScript
- 使用 2 空格缩进
- 组件使用 PascalCase

## 注意事项
- 不要修改 src/generated/ 目录
- 环境变量在 .env.local 中配置
```

### 第四步：知识关联

- CLAUDE.md 文件位置有优先级：管理策略 > 项目级 > 用户级
- 建议 200 行以内，过长会降低遵循度
- 可以用 `.claude/rules/` 目录拆分详细规则
- 见 [06-best-practices.md](06-best-practices.md) 学习更多配置技巧

## 知识点 4：@ 文件引用

### 第一步：概念解释（简单语言）

用 `@` 符号可以快速引用文件。Claude 会自动读取你引用的文件内容。

### 第二步：类比理解（生活例子）

就像在对话中递给对方一份文件——对方可以直接看到内容，不用你去描述。

### 第三步：代码实践（动手实验）

**引用单个文件：**
```text
> 解释 @src/utils/parser.ts 的逻辑
```

**对比多个文件：**
```text
> 对比 @src/api/v1/user.ts 和 @src/api/v2/user.ts 的差异
```

**引用目录：**
```text
> 分析 @src/auth 目录下的所有文件
```

### 第四步：知识关联

- Claude 会自动探索项目，但 `@` 引用更精准
- 减少不必要的文件读取，节省上下文
- 结合 Plan 模式进行深度分析

## 知识点 5：Auto Memory（自动记忆）

### 第一步：概念解释（简单语言）

**Auto Memory** 让 Claude 自动记住你告诉它的内容。比如你纠正过 Claude 的错误，它会自动记住，下次不再犯。

### 第二步：类比理解（生活例子）

就像培养新员工——第一次告诉他"我们公司不用分号"，他就记住了。下次写代码自动遵循这个规则。不需要你每次提醒。

### 第三步：代码实践（动手实验）

**启用 Auto Memory**：
```bash
claude /memory auto on
```

**查看记忆内容**：
```bash
claude /memory
```

**Auto Memory 会自动记住**：
- 你纠正过的错误
- 项目特定的构建命令
- 代码风格偏好
- 常用的工作流程

**存储位置**：
```
~/.claude/memory/<project-hash>/AUTO_MEMORY.md
```

**与 CLAUDE.md 的区别**：

| 特性 | CLAUDE.md | Auto Memory |
|------|-----------|-------------|
| 谁写 | 你手动写 | Claude 自动学习 |
| 内容 | 项目规则、架构约定 | 你的偏好、纠正 |
| 范围 | 项目级 | 项目+用户级 |

### 第四步：知识关联

- Auto Memory 是 Claude 的"长期记忆"
- CLAUDE.md 是"项目说明书"
- 两者配合使用，Claude 越来越懂你

## 知识点 6：会话管理

### 第一步：概念解释（简单语言）

Claude Code 会话可以保存、恢复、分支。你可以继续之前的对话，或者从某个点分叉出新会话。

### 第二步：类比理解（生活例子）

就像写作文档——可以打开之前的草稿继续写，也可以复制一份另辟新径。

### 第三步：代码实践（动手实验）

**会话恢复：**

```bash
# 继续最近会话
claude --continue

# 选择历史会话
claude --resume
```

**会话命令：**

| 命令 | 说明 |
|------|------|
| `/resume` | 恢复会话（别名：`/continue`） |
| `/rename [name]` | 重命名当前会话 |
| `/branch [name]` | 创建会话分支（别名：`/fork`） |

### 第四步：知识关联

- 会话存储在本地
- 可以从 PR 恢复会话：`claude --from-pr 123`
- 会话支持 Remote Control 远程访问

## 知识点 6：Subagents 子代理

### 第一步：概念解释（简单语言）

Subagents 是 Claude Code 创建的子任务代理。它们独立处理探索性任务，完成后返回报告，不污染主会话的上下文。

### 第二步：类比理解（生活例子）

就像项目经理派调查员去调研——调查员做完报告，项目经理只看摘要，不需要知道调研过程的细节。

### 第三步：代码实践（动手实验）

**创建子代理：**
```text
> 使用 subagent 来分析数据库连接池的实现细节，然后返回一份报告
```

**适合子代理的任务：**
- 探索大型代码库
- 调研特定实现
- 安全审查
- 复杂搜索

### 第四步：知识关联

- 子代理完成后自动向主会话汇报
- 避免探索性任务污染主会话上下文
- 见 [05-advanced.md](05-advanced.md) 了解 Agent SDK

## 知识点 7：Git 工作流

### 第一步：概念解释（简单语言）

Claude Code 可以直接操作 Git——提交代码、创建分支、打开 Pull Request。

### 第二步：类比理解（生活例子）

就像有个助手帮你填表格、盖章、提交文件——你只需要说"提交"，他完成所有步骤。

### 第三步：代码实践（动手实验）

**提交更改：**
```text
> 提交当前更改，commit message 要描述清楚修改了什么和为什么
```

**创建 PR：**
```text
> 创建一个 PR，标题是 "feat: 添加用户认证功能"
```

**从 PR 恢复会话：**
```bash
claude --from-pr 123
```

### 第四步：知识关联

- Claude 自动写 commit message
- 可以在 CI 中使用 [GitHub Actions](https://code.claude.com/docs/en/github-actions)
- 结合 worktree 实现并行开发
