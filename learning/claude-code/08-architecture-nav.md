## 章节 1：Harness 管理层

### 核心职责

```
Harness = 管理层（协调者）

职责：
├── Sessions       会话管理（保存、恢复、分支）
├── Permissions    权限控制（Allow/Deny/Ask）
├── Context        上下文管理（Token 统计、压缩）
├── Tool Selection 工具选择（根据意图匹配）
└── Extensions     扩展集成（MCP、Skills、Hooks）
```

### 关键设计

| 功能 | 设计要点 | 源码位置 |
|------|----------|----------|
| 会话管理 | Checkpoints 快照、Fork 分支 | `state/sessions.ts` |
| 权限模型 | 三级权限（allow/deny/ask） | 每个工具的 `checkPermission()` |
| 上下文管理 | Token 统计、智能压缩 | Query Engine |

### 学习要点

1. **权限模式切换**：`/plan`（只显示）→ `/auto`（自动执行）→ `/accept`（接受编辑）
2. **会话恢复**：`claude --continue` 恢复最近会话
3. **上下文压缩**：`/compact` 压缩旧对话

## 章节 3：Tools 工具层

### 工具分类（~40 个）

```
工具系统架构：

├── 文件操作（File Operations）
│   ├── FileReadTool      读取文件（支持图片、PDF）
│   ├── FileEditTool      编辑文件（精确字符串替换）
│   ├── FileWriteTool     创建/覆盖文件
│   └── GlobTool          文件模式匹配
│
├── 内容搜索（Search）
│   ├── GrepTool          正则搜索
│   └── LSPTool           LSP 语言服务
│
├── 命令执行（Execution）
│   ├── BashTool          Shell 命令（支持后台、沙箱）
│   └── TestRunner        测试运行
│
├── 网络请求（Web）
│   ├── WebFetchTool      获取网页
│   ├── WebSearchTool     Web 搜索
│   └── MCPTool           MCP 工具桥接
│
└── 代理扩展（Agent）
    ├── AgentTool         启动子代理
    └── SkillTool         调用预定义技能
```

### 工具接口设计

```typescript
// 每个工具的统一接口
interface Tool {
  name: string;           // 工具名称
  description: string;    // 工具描述（触发关键词）
  inputSchema: Schema;    // 输入参数 Schema（Zod）
  outputSchema: Schema;   // 输出结果 Schema
  
  // 执行方法
  execute(input: Input): Promise<Output>;
  
  // 权限检查
  checkPermission(input: Input): PermissionResult;
}

// 权限结果
type PermissionResult = 
  | { behavior: 'allow' }                      // 自动允许
  | { behavior: 'deny'; message: string }      // 拒绝
  | { behavior: 'ask';                         // 询问用户
      message: string;
      options: PermissionOption[] }
```

### 核心设计思想

> **Everything is a Tool**：每个能力都是独立、可组合、权限可控的工具。

好处：
- **隔离性**：一个工具出错不影响其他
- **可测试**：每个工具独立测试
- **可扩展**：添加新能力只需添加新工具
- **可控制**：每个工具有独立权限

## 章节 4：Agentic Loop

### 循环流程

```
用户提问
    │
    ▼
┌──────────────────────────────────────────────┐
│              Agentic Loop                    │
├──────────────────────────────────────────────┤
│                                              │
│  1. Gather Context（收集上下文）              │
│     ├── 读取相关文件                         │
│     ├── 搜索代码                             │
│     └── 加载记忆                             │
│                                              │
│  2. Take Action（执行操作）                  │
│     ├── 选择工具                             │
│     ├── 执行工具                             │
│     └── 处理结果                             │
│                                              │
│  3. Verify Results（验证结果）               │
│     ├── 检查是否完成                         │
│     ├── 发现新问题                           │
│     └── 决定下一步                           │
│                                              │
│  4. Loop or Stop（循环或停止）               │
│     ├── 未完成 → 继续循环                    │
│     └── 已完成 → 返回结果                    │
│                                              │
└──────────────────────────────────────────────┘
```

### Query Engine（46,000+ 行）

```
Query Engine 职责：

├── API 调用
│   ├── 流式响应处理
│   ├── Token 统计
│   └── 错误处理/重试
│
├── 工具协调
│   ├── 解析工具调用请求
│   ├── 执行工具
│   ├── 返回结果给模型
│
├── 状态管理
│   ├── 保存 Checkpoint
│   ├── 更新记忆
│   ├── 压缩上下文
│
└── 循环控制
    ├── 判断是否继续
    ├── 处理边界情况
    └── 超时保护
```

│  第三层：长期记忆（Auto Memory）                                │

### Token 优化策略

| 策略 | 方法 | 效果 |
|------|------|------|
| CLAUDE.md 控制 | 控制在 200 行以内 | 节省启动开销 |
| 文件选择性读取 | 只读必要文件 | 避免大量 tokens |
| 使用 Subagent | 大型任务用子代理 | 独立上下文 |
| 定期压缩 | `/compact` | 压缩旧对话 |

## 章节 6：Subagents 子代理

### 子代理架构

```
主会话                          Subagent
   │                               │
   │  1. 分配任务                  │
   │  "研究数据库设计"             │
   ├──────────────────────────────►│
   │                               │
   │                      2. 加载独立上下文
   │                         (全新 200K)
   │                               │
   │                      3. 执行工作
   │                         文件读取不计入主会话
   │                               │
   │  4. 返回摘要                  │
   │  +420 tokens                  │
   │◄──────────────────────────────┤
   │                               │
   │  5. 主会话节省                │
   │  6,100 - 420 = 5,680 tokens   │
   │                               │
```

### 适用场景

| 场景 | 为什么用 Subagent |
|------|-------------------|
| 探索性研究 | 需要大量文件读取 |
| 大型分析 | 避免污染主会话 |
| 并行任务 | 多个子代理同时工作 |
| 容错尝试 | 失败不影响主会话 |

## 章节 7：MCP/Skills 扩展

### MCP（Model Context Protocol）

```
MCP = 外部工具连接协议

架构：
├── Stdio Transport    本地进程通信
├── HTTP/SSE Transport 网络通信
└── Resources          文件/数据访问
├── Tools              操作接口
└── Prompts            预定义提示

配置位置：
~/.claude/mcp.json

示例：
{
  "mcpServers": {
    "database": {
      "command": "uvx",
      "args": ["mcp-server-database"],
      "env": { "DB_URL": "..." }
    }
  }
}
```

### Skills（预定义命令）

```
Skills = 自定义工作流

位置：
~/.claude/skills/<skill-name>/SKILL.md

结构：
├── SKILL.md       (必需) 技能描述和指令
├── scripts/      (可选) 执行脚本
├── references/   (可选) 参考文档
└── assets/       (可选) 输出资源

触发方式：
description 中包含触发关键词
```

## 章节 8：落地实践

> **从 Claude Code 源码学习 → OpenClaw Skills 编写**

### Claude Code → OpenClaw 对照

| Claude Code | OpenClaw | 说明 |
|-------------|----------|------|
| Tools | 内置工具 | `read`, `write`, `edit`, `exec`, `browser`, ... |
| MCP | MCP (mcporter) | 通过 MCP 协议连接外部服务 |
| Skills | Skills | 自定义工作流，SKILL.md 格式相同 |
| CLAUDE.md | AGENTS.md / USER.md | 项目规则和用户偏好 |
| Auto Memory | MEMORY.md / memory/*.md | 长期记忆 |
| Subagents | sessions_spawn | 子代理，独立上下文 |

### Skill 编写要点（从源码学习）

```
核心原则（从 Claude Code 工具设计学到的）：

1. 工具化设计
   ├── 每个能力是独立工具
   ├── 统一接口（名称、描述、输入Schema、输出Schema）
   └── 权限控制（allow/deny/ask）

2. 渐进式披露
   ├── SKILL.md 只写核心流程
   ├── 详细内容放 references/
   └── 脚本放 scripts/

3. 触发机制
   ├── description 写清楚触发条件
   ├── 包含关键词和场景
   └── 避免与其他 Skill 冲突

4. Token 效率
   ├── SKILL.md 控制在 500 行以内
   ├── 只加载必要信息
   └── 使用脚本而非文字描述
```

## 架构对比：Claude Code vs OpenClaw

| 架构层 | Claude Code | OpenClaw | 差异 |
|--------|-------------|----------|------|
| 运行时 | Bun | Node.js | 不同运行时 |
| UI 框架 | Ink (终端) | 多渠道 (Telegram/Discord/...) | OpenClaw 支持更多渠道 |
| 工具数量 | ~40 内置 | ~15 内置 + MCP 扩展 | OpenClaw 更依赖 MCP |
| 记忆系统 | 文件系统 | 文件系统 | 类似 |
| 子代理 | swarms | sessions_spawn | 类似概念 |
| Skills | Skills | Skills | 格式相同 |
