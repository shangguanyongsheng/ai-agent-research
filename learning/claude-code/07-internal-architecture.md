## 知识点 1：Agentic Loop（代理循环）

### 第一步：概念解释（简单语言）

Claude Code 的核心是一个**循环**：收到任务 → 思考 → 行动 → 观察 → 继续思考，直到完成。

这个循环不是固定的流程，而是**动态调整**的——每一步的结果会影响下一步做什么。

### 第二步：类比理解（生活例子）

就像一个**侦探破案**：

```
收到案件（用户提问）
    │
    ▼
┌─────────────────────────────────────┐
│ 第1轮循环                            │
│                                     │
│ 思考："先看看现场有什么线索"          │
│ 行动：检查现场（读取相关文件）         │
│ 观察："发现了嫌疑人的指纹"            │
│                                     │
│ 判断：案件没破，继续                  │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│ 第2轮循环                            │
│                                     │
│ 思考："指纹指向谁？去查数据库"         │
│ 行动：查询数据库（运行命令）           │
│ 观察："找到了嫌疑人张三"              │
│                                     │
│ 判断：案件没破，继续                  │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│ 第3轮循环                            │
│                                     │
│ 思考："张三有不在场证明吗？"           │
│ 行动：询问证人（搜索更多信息）         │
│ 观察："证人说他确实在别处"            │
│                                     │
│ 判断：嫌疑排除，重新思考               │
└─────────────────────────────────────┘
    │
    ▼
    ... 继续循环 ...
    │
    ▼
案件告破（任务完成）
```

│  │                                                          │  │

│  │   │ Gather   │───→│  Take    │───→│ Verify   │         │  │
│  │   │ Context  │    │  Action  │    │ Results  │         │  │
│  │   │ 收集上下文│    │ 执行操作  │    │ 验证结果  │         │  │
│  │   └──────────┘    └──────────┘    └──────────┘         │  │
│  │        │               │               │                │  │
│  │        │               │               │                │  │
│  │        └───────────────┴───────────────┘                │  │
│  │                        │                                 │  │

│  │        │ 继续循环 │      │ 返回结果 │                   │  │

- **Models**：负责"思考"部分

## 知识点 2：三层架构

### 第一步：概念解释（简单语言）

Claude Code 的架构分三层：

| 层级 | 名称 | 职责 |
|------|------|------|
| **模型层** | Models | 思考、推理、决策 |
| **工具层** | Tools | 执行具体操作 |
| **管理层** | Harness | 协调模型和工具 |

### 第二步：类比理解（生活例子）

就像一个**公司**：

```
┌─────────────────────────────────────────────────────────────────┐
│                        公司架构                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  管理层（Harness）                                              │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  CEO/项目经理：                                           │  │
│  │  • 接收任务                                               │  │
│  │  • 分配工作                                               │  │
│  │  • 协调资源                                               │  │
│  │  • 管理进度                                               │  │
│  └─────────────────────────────────────────────────────────┘  │
│                              │                                  │
│                              ▼                                  │
│  智囊层（Models）                                               │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  顾问团队：                                               │  │
│  │  • 分析问题                                               │  │
│  │  • 制定方案                                               │  │
│  │  • 评估风险                                               │  │
│  │  • 给出建议                                               │  │
│  └─────────────────────────────────────────────────────────┘  │
│                              │                                  │
│                              ▼                                  │
│  执行层（Tools）                                                │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐     │
│  │ 文件操作  │  │ 代码搜索  │  │ 命令执行  │  │ 网络请求  │     │
│  │ 秘书     │  │ 情报员    │  │ 技术员    │  │ 联络员    │     │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 第三步：架构详解

**模型层（Models）**：
```
职责：推理和决策

支持的模型：
├── Claude Sonnet    → 大多数任务（默认）
├── Claude Opus      → 复杂推理、架构决策
└── Claude Haiku     → 快速响应、简单任务

切换方式：
claude --model opus
或会话中：/model opus
```

**工具层（Tools）**：
```
五大类工具：

1. File Operations（文件操作）
   ├── Read     读取文件
   ├── Edit     编辑文件
   ├── Create   创建文件
   └── Rename   重命名/移动

2. Search（搜索）
   ├── Glob     按模式找文件
   ├── Grep     正则搜索内容
   └── Explore  探索代码库

3. Execution（执行）
   ├── Bash     运行命令
   ├── Test     运行测试
   └── Git      Git 操作

4. Web（网络）
   ├── Search   搜索网络
   ├── Fetch    获取网页
   └── Docs     查阅文档

5. Code Intelligence（代码智能）
   ├── TypeCheck  类型检查
   ├── GotoDef    跳转定义
   └── FindRefs   查找引用
```

**管理层（Harness）**：
```
核心职责：

1. 会话管理
   ├── Checkpoints  快照/撤销
   ├── Permissions  权限控制
   └── Resume/Fork  恢复/分支

2. 上下文管理
   ├── Load CLAUDE.md
   ├── Load Auto Memory
   ├── Compact Context
   └── Track Token Usage

3. 工具协调
   ├── Tool Selection
   ├── Tool Execution
   └── Result Processing

4. 扩展集成
   ├── MCP Servers
   ├── Skills
   ├── Hooks
   └── Subagents
```

### 第四步：知识关联

```
                Harness（管理层）
                     │
         ┌───────────┼───────────┐
         │           │           │
         ▼           ▼           ▼
    Sessions     Context      Tools
    会话管理     上下文管理    工具协调
         │           │           │
         └───────────┴───────────┘
                     │
                     ▼
                Models（模型层）
                推理和决策
```

## 知识点 3：Context Window（上下文窗口）

### 第一步：概念解释（简单语言）

Context Window 就像 Claude 的"工作记忆"——存储当前会话中所有相关的信息。但它是有限的，需要合理管理。

### 第二步：类比理解（生活例子）

就像一个**白板**：

```
┌─────────────────────────────────────────────────────────────────┐
│                        白板（200K tokens）                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 启动时自动写入：                                           │  │
│  │                                                          │  │
│  │ System Prompt    ~4.2K  → 核心指令（你看不到）            │  │
│  │ Auto Memory      ~0.7K  → Claude 的学习笔记               │  │
│  │ Environment      ~0.3K  → 环境信息                        │  │
│  │ MCP Tools        ~0.1K  → 工具列表                        │  │
│  │ Skills           ~0.5K  → 技能描述                        │  │
│  │ CLAUDE.md        ~2K    → 项目规则                        │  │
│  │                                                          │  │
│  │ 小计：~8K tokens（还没开始干活就用了 4%）                  │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 工作时写入：                                               │  │
│  │                                                          │  │
│  │ 你的问题         +45    tokens                           │  │
│  │ 读取 auth.ts     +2400  tokens  ← 文件读取很贵！          │  │
│  │ 读取 tokens.ts   +1100  tokens                           │  │
│  │ Claude 分析      +800   tokens                           │  │
│  │ 编辑 auth.ts     +400   tokens                           │  │
│  │ npm test 输出    +1200  tokens  ← 命令输出也占空间        │  │
│  │                                                          │  │
│  │ 小计：+6K tokens                                          │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 空间不足时：                                               │  │
│  │                                                          │  │
│  │ /compact  → 压缩旧对话，保留关键信息                       │  │
│  │ /clear    → 清空重来                                      │  │
│  │ Subagent  → 子代理独立上下文                              │  │
│  │                                                          │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 第三步：Token 成本分析

| 内容 | Token 成本 | 说明 |
|------|-----------|------|
| System Prompt | ~4,200 | 固定开销 |
| CLAUDE.md | ~1,800 | 建议 < 200 行 |
| Auto Memory | ~680 | 自动学习 |
| 文件读取 | 变化大 | **主要开销** |
| 命令输出 | 变化大 | 可被压缩 |
| Subagent | 0 | 独立上下文 |

### 第四步：知识关联

- `/compact` 压缩会释放空间
- Subagent 的文件读取不计入主会话
- CLAUDE.md 太长会浪费空间

## 知识点 4：Sessions 和 Checkpoints

### 第一步：概念解释（简单语言）

**Sessions**：每个对话是一个会话，可以保存、恢复、分支。

**Checkpoints**：每次编辑文件前，Claude 会保存快照，你可以撤销。

### 第二步：类比理解（生活例子）

就像**游戏存档**：

```
Sessions（会话）= 游戏进度

┌─────────────────────────────────────────────────────────────────┐
│                        存档系统                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Save 1 (Session A)                                            │
│  ├── 进度：第3章                                               │
│  ├── 物品：已完成登录功能                                       │
│  └── 时间：2026-03-31 10:00                                    │
│                                                                 │
│  Save 2 (Session A - Fork)                                     │
│  ├── 进度：第3章（分支）                                        │
│  ├── 物品：尝试了不同的登录方案                                  │
│  └── 时间：2026-03-31 10:30                                    │
│                                                                 │
│  Checkpoints（快照）= 撤销点                                    │
│                                                                 │
│  Checkpoint 1: 编辑 auth.ts 之前                               │
│  Checkpoint 2: 编辑 middleware.ts 之前                         │
│  Checkpoint 3: 编辑 test.ts 之前                               │
│                                                                 │
│  按 ESC ESC → 回到上一个 Checkpoint                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 第三步：会话命令

```bash
# 恢复最近的会话
claude --continue

# 选择历史会话
claude --resume

# 分支当前会话
claude --continue --fork-session

# 查看会话状态
claude /status
```

### 第四步：知识关联

- Checkpoints 只保存文件变更，不保存远程操作
- 多个终端恢复同一会话会交错消息
- Fork 可以尝试不同方案而不影响原会话

## 知识点 5：Subagents（子代理）架构

### 第一步：概念解释（简单语言）

Subagent 是独立的代理，有自己独立的上下文窗口。主会话不会被 Subagent 的文件读取污染。

### 第二步：类比理解（生活例子）

就像**外包团队**：

```
┌─────────────────────────────────────────────────────────────────┐
│                      外包架构                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  主项目团队（主会话）                                            │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │                                                         │  │
│  │  项目经理：你                                            │  │
│  │  核心工程师：Claude（主）                                 │  │
│  │                                                         │  │
│  │  白板空间：100K tokens                                   │  │
│  │                                                         │  │
│  └─────────────────────────────────────────────────────────┘  │
│                              │                                  │
│                              │ 外包任务                         │
│                              ▼                                  │
│  外包团队（Subagent）                                           │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │                                                         │  │
│  │  任务：研究数据库设计                                     │  │
│  │                                                         │  │
│  │  独立白板：200K tokens（全新空间）                        │  │
│  │                                                         │  │
│  │  文件读取：                                              │  │
│  │    ├── db/schema.sql    +2,200 tokens                   │  │
│  │    ├── db/migrations/   +3,100 tokens                   │  │
│  │    └── config/db.ts     +800 tokens                     │  │
│  │                                                         │  │
│  │  总计：6,100 tokens（不占用主会话空间）                    │  │
│  │                                                         │  │
│  └─────────────────────────────────────────────────────────┘  │
│                              │                                  │
│                              │ 只返回摘要                       │
│                              ▼                                  │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  返回结果：420 tokens（结论 + 建议）                      │  │
│  │                                                         │  │
│  │  主会话节省：6,100 - 420 = 5,680 tokens                  │  │
│  │                                                         │  │
│  └─────────────────────────────────────────────────────────┘  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 第三步：Subagent 流程

```
主会话                          Subagent
   │                               │
   │  1. 分配任务                  │
   │  "研究数据库设计"             │
   ├──────────────────────────────►│
   │                               │
   │                      2. 加载独立上下文
   │                         CLAUDE.md（副本）
   │                         MCP 工具
   │                         Skills
   │                               │
   │                      3. 执行工作
   │                         读取文件
   │                         分析推理
   │                         编写代码
   │                               │
   │  4. 返回摘要                  │
   │  +420 tokens                  │
   │◄──────────────────────────────┤
   │                               │
   │  5. 继续工作                  │
   │                               │
```

### 第四步：知识关联

- Subagent 不继承主会话的 Auto Memory
- Subagent 的文件读取不污染主会话
- 适合探索性任务、大型分析
