## 知识点 1：Agentic Loop（代理循环）

### 第一步：概念解释（简单语言）

Claude Code 的核心是一个**循环**：收到任务 → 思考 → 行动 → 观察 → 继续思考，直到完成。

这个循环不是固定的流程，而是**动态调整**的——每一步的结果会影响下一步做什么。

### 第二步：类比理解（生活例子）

就像一个**侦探破案**：

```
收到案件（用户提问）
    │
    ▼
┌─────────────────────────────────────┐
│ 第1轮循环                            │
│                                     │
│ 思考："先看看现场有什么线索"          │
│ 行动：检查现场（读取相关文件）         │
│ 观察："发现了嫌疑人的指纹"            │
│                                     │
│ 判断：案件没破，继续                  │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│ 第2轮循环                            │
│                                     │
│ 思考："指纹指向谁？去查数据库"         │
│ 行动：查询数据库（运行命令）           │
│ 观察："找到了嫌疑人张三"              │
│                                     │
│ 判断：案件没破，继续                  │
└─────────────────────────────────────┘
    │
    ▼
    ... 继续循环 ...
    │
    ▼
案件告破（任务完成）
```

```
│  │   │ Context  │    │  Action  │    │ Results  │         │  │
```

### 第四步：知识关联

- **Models**：负责"思考"部分（调用 Claude API）
- **Tools**：负责"行动"部分（执行具体操作）
- **Context Window**：存储"观察"结果（会话历史）
- **Query Engine**：管理整个循环流程（46,000+ 行代码）

## 知识点 2：三层架构

### 第一步：概念解释（简单语言）

Claude Code 的架构分三层：

| 层级 | 名称 | 职责 | 代码规模 |
|------|------|------|----------|
| **模型层** | Models | 思考、推理、决策 | API 调用 |
| **工具层** | Tools | 执行具体操作 | ~40 个工具 |
| **管理层** | Harness | 协调模型和工具 | 核心逻辑 |

### 第二步：类比理解（生活例子）

就像一个**公司**：

```
┌─────────────────────────────────────────────────────────────────┐
│                        公司架构                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  管理层（Harness）                                              │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  CEO/项目经理：                                           │  │
│  │  • 接收任务                                               │  │
│  │  • 分配工作                                               │  │
│  │  • 协调资源                                               │  │
│  │  • 管理进度                                               │  │
│  │  • 权限控制                                               │  │
│  │  • 会话管理                                               │  │
│  └─────────────────────────────────────────────────────────┘  │
│                              │                                  │
│                              ▼                                  │
│  智囊层（Models）                                               │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  顾问团队：                                               │  │
│  │  • 分析问题                                               │  │

│  └──────────┘  └──────────┘  └──────────┘  └──────────┘     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 第三步：架构详解

**模型层（Models）**：
```typescript
// 模型切换
claude --model opus     // 使用 Opus 进行复杂推理
claude --model haiku    // 使用 Haiku 进行快速响应
claude --model sonnet   // 默认模型

// 会话中切换
/model opus
/model haiku
/model sonnet
```

**工具层（Tools）~40 个工具**：
```
工具分类：

1. 文件操作（File Operations）
   ├── FileReadTool      读取文件（支持图片、PDF、Jupyter）
   ├── FileEditTool      编辑文件，精确字符串替换
   ├── FileWriteTool     创建或覆盖文件
   └── GlobTool          文件模式匹配搜索

2. 内容搜索（Search）
   ├── GrepTool          正则内容搜索
   └── LSPTool           LSP 语言服务集成

3. 命令执行（Execution）
   ├── BashTool          执行 Shell 命令（支持后台、沙箱）
   └── TestRunner        测试运行器

4. 网络请求（Web）
   ├── WebFetchTool      获取网页内容
   └── WebSearchTool     Web 搜索

5. 代理扩展（Agent）
   ├── AgentTool         多代理系统，启动子代理
   ├── MCPTool           MCP 工具调用桥接
   └── SkillTool         调用预定义技能
```

**管理层（Harness）**：
```
核心职责：

1. 会话管理
   ├── Checkpoints      快照/撤销
   ├── Permissions      权限控制（Allow/Deny/Ask）
   ├── Resume/Fork      恢复/分支会话
   └── Compact           压缩上下文

2. 上下文管理
   ├── Load CLAUDE.md    项目规则
   ├── Load Auto Memory  自动学习
   ├── Track Tokens      Token 使用统计
   └── Compact Context   智能压缩

3. 工具协调
   ├── Tool Selection    根据意图选择工具
   ├── Tool Execution    安全执行
   ├── Result Processing 处理返回结果
   └── Error Handling    错误处理和重试

4. 扩展集成
   ├── MCP Servers       外部服务连接
   ├── Skills            自定义命令
   ├── Hooks             事件钩子
   └── Subagents         子代理
```

### 第四步：知识关联

```
                Harness（管理层）

         ┌───────────┼───────────┐
         │           │           │
         ▼           ▼           ▼
    Sessions     Context      Tools
    会话管理     上下文管理    工具协调
         │           │           │
         └───────────┴───────────┘
                     │
                     ▼
                Models（模型层）
                推理和决策
```

## 知识点 3：五大核心子系统

### 第一步：概念解释（简单语言）

Claude Code 由五个核心子系统组成，每个负责一个关键领域：

| 子系统 | 职责 | 代码规模 |
|--------|------|----------|
| 工具系统 | 提供各种能力 | ~40 个工具 |
| 查询引擎 | LLM 交互和流程编排 | 46,000+ 行 |
| 多代理编排 | 子代理管理 | 核心模块 |
| IDE 桥接 | 编辑器集成 | VS Code/JetBrains |
| 持久化记忆 | 跨会话记忆 | 文件系统 |

### 第二步：类比理解（生活例子）

就像一个**智能工厂**：

```
┌─────────────────────────────────────────────────────────────────┐
│                      智能工厂架构                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1️⃣ 工具系统（Tool System）= 生产设备                           │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  每个工具 = 一台机器：                                     │  │
│  │  • 切割机（文件读取）                                      │  │
│  │  • 焊接机（文件编辑）                                      │  │
│  │  • 检测机（代码搜索）                                      │  │
│  │  • 运输带（命令执行）                                      │  │
│  │                                                          │  │
│  │  特点：独立、可组合、权限可控                               │  │
│  └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│  2️⃣ 查询引擎（Query Engine）= 中央控制室                        │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  46,000+ 行代码的核心：                                     │  │
│  │  • 接收订单（用户请求）                                    │  │
│  │  • 分配任务（调用模型）                                    │  │
│  │  • 协调设备（工具调度）                                    │  │

│                                                                 │
```

### 第三步：子系统详解

**工具系统设计模式**：
```typescript
// 每个工具都有统一接口
interface Tool {
  name: string;           // 工具名称
  description: string;    // 工具描述
  inputSchema: Schema;    // 输入参数 Schema
  outputSchema: Schema;   // 输出结果 Schema
  
  // 执行方法
  execute(input: Input): Promise<Output>;
  
  // 权限检查
  checkPermission(input: Input): PermissionResult;
}

// 权限结果类型
type PermissionResult = 
  | { behavior: 'allow' }                      // 直接允许
  | { behavior: 'deny'; message: string }      // 拒绝
  | { behavior: 'ask'; message: string;        // 询问用户
      options: PermissionOption[] }
```

## 知识点 4：Context Window（上下文窗口）

### 第一步：概念解释（简单语言）

Context Window 就像 Claude 的"工作记忆"——存储当前会话中所有相关的信息。但它是有限的，需要合理管理。

### 第二步：类比理解（生活例子）

就像一个**白板**：

```
┌─────────────────────────────────────────────────────────────────┐
│                        白板（200K tokens）                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 启动时自动写入：                                           │  │
│  │                                                          │  │
│  │ System Prompt    ~4.2K  → 核心指令（你看不到）            │  │
│  │ Auto Memory      ~0.7K  → Claude 的学习笔记               │  │
│  │ Environment      ~0.3K  → 环境信息                        │  │
│  │ MCP Tools        ~0.1K  → 工具列表                        │  │
│  │ Skills           ~0.5K  → 技能描述                        │  │
│  │ CLAUDE.md        ~2K    → 项目规则                        │  │
│  │                                                          │  │
│  │ 小计：~8K tokens（还没开始干活就用了 4%）                  │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 工作时写入：                                               │  │
│  │                                                          │  │
│  │ 你的问题         +45    tokens                           │  │
│  │ 读取 auth.ts     +2400  tokens  ← 文件读取很贵！          │  │
│  │ 读取 tokens.ts   +1100  tokens                           │  │
│  │ Claude 分析      +800   tokens                           │  │
│  │ 编辑 auth.ts     +400   tokens                           │  │
│  │ npm test 输出    +1200  tokens  ← 命令输出也占空间        │  │
│  │                                                          │  │
│  │ 小计：+6K tokens                                          │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 空间不足时：                                               │  │
│  │                                                          │  │
```

### 第三步：Token 成本分析

| 内容 | Token 成本 | 说明 | 优化建议 |
|------|-----------|------|----------|
| System Prompt | ~4,200 | 固定开销 | 无法优化 |
| CLAUDE.md | ~1,800 | 项目规则 | **控制在 200 行以内** |
| Auto Memory | ~680 | 自动学习 | 定期清理 |
| 文件读取 | 变化大 | **主要开销** | 只读必要文件 |
| 命令输出 | 变化大 | 可被压缩 | 使用 /compact |
| Subagent | 0 | 独立上下文 | **大型任务用子代理** |

### 第四步：知识关联

- `/compact` 压缩会释放空间
- Subagent 的文件读取不计入主会话
- CLAUDE.md 太长会浪费空间
- 使用 `.claudeignore` 排除不需要的文件

## 知识点 5：Sessions 和 Checkpoints

### 第一步：概念解释（简单语言）

**Sessions**：每个对话是一个会话，可以保存、恢复、分支。

**Checkpoints**：每次编辑文件前，Claude 会保存快照，你可以撤销。

### 第二步：类比理解（生活例子）

就像**游戏存档**：

```
Sessions（会话）= 游戏进度

┌─────────────────────────────────────────────────────────────────┐
│                        存档系统                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Save 1 (Session A)                                            │
│  ├── 进度：第3章                                               │
│  ├── 物品：已完成登录功能                                       │
│  └── 时间：2026-03-31 10:00                                    │
│                                                                 │
│  Save 2 (Session A - Fork)                                     │
│  ├── 进度：第3章（分支）                                        │
│  ├── 物品：尝试了不同的登录方案                                  │
│  └── 时间：2026-03-31 10:30                                    │
│                                                                 │
│  Checkpoints（快照）= 撤销点                                    │
│                                                                 │
│  Checkpoint 1: 编辑 auth.ts 之前                               │
│  Checkpoint 2: 编辑 middleware.ts 之前                         │
│  Checkpoint 3: 编辑 test.ts 之前                               │
│                                                                 │
│  按 ESC ESC → 回到上一个 Checkpoint                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 第三步：会话命令

```bash
# 恢复最近的会话
claude --continue

# 选择历史会话
claude --resume

# 分支当前会话（创建副本，不影响原会话）
claude --continue --fork-session

# 查看会话状态
claude /status
```

### 第四步：知识关联

- Checkpoints 只保存文件变更，不保存远程操作
- 多个终端恢复同一会话会交错消息
- Fork 可以尝试不同方案而不影响原会话
- 会话存储在 `~/.claude/projects/<project>/sessions/`

### 第三步：核心设计模式

**1. 工具化设计（Everything is a Tool）**

```
设计原则：
每个能力都是独立、可组合的工具

好处：
├── 隔离性：一个工具出错不影响其他工具
├── 可测试：每个工具可以独立测试
├── 可扩展：添加新能力只需添加新工具
└── 可控制：每个工具有独立权限

源码体现：
├── ~40 个工具文件
├── 统一的 Tool 接口
├── 独立的权限检查函数
└── 可配置的工具白名单/黑名单
```

**2. 权限模型（Permission Model）**

```typescript
// 源码中的权限类型
type PermissionResult = 
  | { behavior: 'allow' }                      // 自动允许
  | { behavior: 'deny'; message: string }      // 拒绝执行
  | { behavior: 'ask';                         // 询问用户
      message: string;
      options: PermissionOption[] }

// 权限模式
type PermissionMode = 
  | 'plan'     // 计划模式：只显示将要做什么
  | 'auto'     // 自动模式：自动执行（危险操作除外）
  | 'accept'   // 接受模式：自动接受所有编辑

// 权限粒度
├── 文件级：哪些文件可以访问
├── 命令级：哪些命令可以执行
├── 网络级：哪些域名可以访问
└── 工具级：哪些工具可以使用
```

**3. 流式处理（Streaming）**

```
设计原则：
所有输出都是流式的，用户立即看到进度

好处：
├── 实时反馈：不用等待完成
├── 可中断：随时可以停止
├── 可观察：看到 AI 思考过程
└── 低延迟：用户体验好

源码体现：
├── 使用 Anthropic SDK 的流式 API
├── React Ink 实现终端实时渲染
├── 每个工具调用后立即显示结果
└── 支持中途取消（Ctrl+C）
```

**4. 记忆系统（Memory System）**

```
三层记忆架构：

1. 工作记忆（Context Window）
   ├── 当前会话的所有信息
   ├── 有限容量（200K tokens）
   └── 自动压缩（/compact）

2. 短期记忆（Session State）
   ├── 会话历史
   ├── 文件快照（Checkpoints）
   └── 存储在 ~/.claude/projects/

3. 长期记忆（Auto Memory）
   ├── 自动学习的用户偏好
   ├── 项目特定的规则
   └── 存储在 CLAUDE.md / MEMORY.md
```

**5. 多代理编排（Multi-Agent）**

```
设计原则：
复杂任务拆分给专门的子代理

好处：
├── 上下文隔离：子代理不污染主会话
├── 并行执行：多个子代理同时工作
├── 专业分工：不同任务用不同的提示词
└── 容错性：一个子代理失败不影响其他

源码体现：
├── swarms/ 目录：多代理实现
├── 独立的上下文窗口
├── 独立的工具权限
└── 只返回摘要给主会话
```

### 第四步：知识关联

| 设计模式 | 解决的问题 | 对应源码位置 |
|---------|-----------|-------------|
| 工具化设计 | 能力隔离、可扩展 | `tools/` 目录 |
| 权限模型 | 安全控制 | 每个工具的权限检查 |
| 流式处理 | 用户体验 | Query Engine |
| 记忆系统 | 上下文管理 | `state/` 目录 |
| 多代理编排 | 复杂任务 | `swarms/` 目录 |

### 第三步：安全机制详解

**权限模型实现**：
```typescript
// 每个工具都有权限检查
interface Tool {
  // 权限检查函数
  checkPermission(input: Input): PermissionResult;
}

// 权限结果
type PermissionResult = 
  | { behavior: 'allow' }                      // 允许
  | { behavior: 'deny'; message: string }      // 拒绝
  | { behavior: 'ask';                         // 询问用户
      message: string;
      options: PermissionOption[] }

// 权限模式
enum PermissionMode {
  PLAN = 'plan',      // 只显示将要做什么
  AUTO = 'auto',      // 自动执行（危险操作除外）
  ACCEPT = 'accept'   // 自动接受所有编辑
}
```

**情感检测实现**：
```typescript
// 源码中的情感检测（使用正则表达式）
```
