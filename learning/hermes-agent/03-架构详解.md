# 03-架构详解

> 理解 Hermes Agent 的底层架构：多模型、多平台、终端后端如何协同工作。

---

## 第一步：概念解释

### Hermes 的整体架构

Hermes Agent 由几个核心模块组成：

| 模块 | 职责 |
|------|------|
| **AIAgent** | 核心 Agent 循环（对话、工具调用、持久化） |
| **HermesCLI** | 终端 UI（交互、命令、会话管理） |
| **Gateway** | 消息平台网关（Telegram/Discord/Slack 等） |
| **Cron** | 定时任务调度器 |
| **ACP Adapter** | 编辑器集成（VS Code/Zed/JetBrains） |

## 第二步：类比理解

### 把 Hermes 想象成一个公司

```
┌────────────────────────────────────────────┐
│           Entry Points（入口）              │
│                                            │
│  CLI      Gateway      ACP     API Server  │
│ (终端)   (消息平台)  (编辑器)   (HTTP)      │
└────────────────────────────────────────────┘
                    ↓
┌────────────────────────────────────────────┐
│           AIAgent（核心员工）               │
│                                            │
│  Prompt Builder   Provider    Tool Dispatch│
│  （构建提示）    （选择模型）  （调用工具）  │
└────────────────────────────────────────────┘
                    ↓
┌──────────────────┐    ┌────────────────────┐
│  Session Storage │    │   Tool Backends    │
│  （SQLite+FTS5） │    │ （终端/浏览器/等） │
└──────────────────┘    └────────────────────┘
```

**类比：**
- CLI/Gateway/ACP → 公司的不同入口（前台、电话、网站）
- AIAgent → 核心员工，处理所有请求
- Session Storage → 档案室，保存所有对话记录
- Tool Backends → 工具部门，执行具体任务

### 数据流

#### CLI 会话流程

```
用户输入
    → HermesCLI.process_input()
    → AIAgent.run_conversation()
    → prompt_builder.build_system_prompt()
    → runtime_provider.resolve_runtime_provider()
    → API 调用（chat_completions / codex_responses / anthropic_messages）
    → 工具调用？
        → model_tools.handle_function_call()
        → 循环
    → 最终响应
    → 显示
    → 保存到 SessionDB
```

#### Gateway 消息流程

```
平台事件
    → Adapter.on_message()
    → MessageEvent
    → GatewayRunner._handle_message()
    → 用户授权
    → 解析会话 key
    → 创建 AIAgent（带会话历史）
    → AIAgent.run_conversation()
    → 通过 Adapter 返回响应
```

#### Cron 任务流程

```
调度器 tick
    → 从 jobs.json 加载到期任务
    → 创建新 AIAgent（无历史）
    → 注入技能作为上下文
    → 运行任务 prompt
    → 交付响应到目标平台
    → 更新任务状态和下次运行时间
```

### 多 Provider 支持

Hermes 支持 18+ Provider，通过 `runtime_provider` 模块统一处理：

| Provider | API 模式 | 认证方式 |
|----------|----------|----------|
| Nous Portal | chat_completions | OAuth |
| OpenRouter | chat_completions | API Key |
| OpenAI | codex_responses | OAuth/API Key |
| Anthropic | anthropic_messages | API Key/OAuth |
| Z.AI/GLM | chat_completions | API Key |
| 自定义端点 | chat_completions | API Key + Base URL |

#### Provider 解析流程

```python
# runtime_provider.py
def resolve_runtime_provider(provider, model):
    # 1. 查找 Provider 配置
    # 2. 获取 API Key/凭证
    # 3. 确定 API 模式
    # 4. 返回 (api_mode, api_key, base_url)
```

### 终端后端

终端工具支持 6 种后端：

| 后端 | 说明 | 用途 |
|------|------|------|
| local | 本地执行 | 开发、信任任务 |
| docker | Docker 容器 | 安全隔离 |
| ssh | 远程服务器 | Agent 无法修改自己的代码 |
| singularity | HPC 容器 | 集群计算 |
| modal | 云端执行 | Serverless |
| daytona | 云沙盒 | 持久远程环境 |

#### 配置示例

```yaml
# ~/.hermes/config.yaml
terminal:
  backend: docker
  docker_image: python:3.11-slim
  container_cpu: 1
  container_memory: 5120  # MB
  container_disk: 51200   # MB
  container_persistent: true
```

### 设计原则

| 原则 | 说明 |
|------|------|
| **Prompt 稳定性** | 系统提示不会在对话中改变 |
| **可观察执行** | 所有工具调用都可见 |
| **可中断** | API 调用和工具执行可随时中断 |
| **平台无关核心** | 一个 AIAgent 服务所有平台 |
| **松耦合** | 可选子系统（MCP/插件/记忆 Provider）通过注册机制 |

---

## 🎯 关键理解

1. **AIAgent 是核心**：所有入口都使用同一个 Agent 类
2. **Provider 统一处理**：18+ Provider 通过 runtime_provider 统一解析
3. **终端后端多样**：可根据安全需求选择 local/docker/ssh/modal
4. **工具自注册**：添加新工具只需导入到 model_tools.py
