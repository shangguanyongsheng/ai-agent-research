# 02-核心概念

> 理解 Hermes Agent 的三大核心机制：学习闭环、技能系统、记忆机制。

---

## 第一步：概念解释

### 什么是学习闭环？

**学习闭环** 是 Hermes Agent 最独特的特性：Agent 能自主学习、改进、记忆，形成完整的闭环。

闭环包含：
1. **Memory（记忆）**：记住用户偏好、环境信息、学到的知识
2. **Skills（技能）**：复杂任务后自动创建技能，下次直接使用
3. **Skill Improvement（技能改进）**：使用中发现问题，自动改进技能
4. **Session Search（会话搜索）**：搜索过去的对话，召回相关知识
5. **Honcho（用户建模）**：跨会话理解用户的深层意图

---

## 第二步：类比理解

### 学习闭环 = 真正的学习过程

传统 AI Agent → 像"一次性员工"，每次对话从零开始
有学习闭环的 Agent → 像"成长型员工"，会：

1. **记忆**：把重要信息记在笔记本（MEMORY.md）
2. **技能**：复杂任务后写操作手册（Skills）
3. **改进**：发现手册有问题，修改手册
4. **搜索**：遇到类似问题，翻看过去的笔记
5. **理解用户**：时间久了，知道你的工作风格

### 类比示例

```
传统 Agent 的对话：
用户："帮我部署这个项目"
Agent："好的，执行命令..."
（下次对话）
用户："再帮我部署另一个项目"
Agent："好的，执行命令..."（从头开始，没记住上次的经验）

Hermes Agent 的对话：
用户："帮我部署这个项目"
Agent："好的，执行命令...（成功）"
→ 自动创建 deploy-project 技能
→ 记录：项目用 Docker compose，端口是 8080

（下次对话）
用户："再帮我部署另一个项目"
Agent："我有个 deploy-project 技能，直接用！"
→ 检查记忆，知道你的项目结构
→ 用技能快速完成
```

## 第三步：代码/实践

### Memory 系统

Memory 由两个文件组成：

| 文件 | 内容 | 限制 |
|------|------|------|
| `MEMORY.md` | Agent 的个人笔记：环境、项目、学到的知识 | 2,200 字符 |
| `USER.md` | 用户画像：偏好、沟通风格、期望 | 1,375 字符 |

存储位置：`~/.hermes/memories/`

#### Memory 的操作

```python
# Agent 使用 memory 工具
memory(action="add", target="memory", content="Project uses Go 1.22 + sqlc")
memory(action="replace", target="memory", old_text="dark mode", content="User prefers light mode")
memory(action="remove", target="memory", old_text="obsolete info")
```

#### Memory 在系统提示中的样子

```
══════════════════════════════════════════════
MEMORY (your personal notes) [67% — 1,474/2,200 chars]
══════════════════════════════════════════════
User's project is a Rust web service at ~/code/myapi using Axum + SQLx
§
This machine runs Ubuntu 22.04, has Docker and Podman installed
§
User prefers concise responses, dislikes verbose explanations
```

### Skills 系统

Skills 是"按需加载的知识文档"，存储在 `~/.hermes/skills/`。

#### Skills 的目录结构

```
~/.hermes/skills/
├── mlops/              # 分类目录
│   ├── axolotl/
│   │   ├── SKILL.md    # 主指令（必需）
│   │   ├── references/ # 参考资料
│   │   ├── templates/  # 输出模板
│   │   └── scripts/    # 可调用脚本
│   └── vllm/
│       └── SKILL.md
├── devops/
│   └── deploy-k8s/     # Agent 创建的技能
│       └── SKILL.md
```

#### Skills 的渐进式加载

```
Level 0: skills_list() → [{name, description}]  # 节省 token
Level 1: skill_view(name) → 完整内容 + 元数据    # 真正需要时才加载
Level 2: skill_view(name, path) → 特定参考文件   # 查看参考资料
```

#### Agent 自动创建技能

```python
# 完成复杂任务后，Agent 自动调用
skill_manage(action="create", name="deploy-api", content="...", category="devops")
skill_manage(action="patch", name="deploy-api", old_string="...", new_string="...")
skill_manage(action="delete", name="deploy-api")
```

---

### Session Search（会话搜索）

所有 CLI 和消息会话存储在 SQLite (`~/.hermes/state.db`)，支持 FTS5 全文本搜索。

```bash
hermes sessions list  # 查看过去的会话
```

```python
# Agent 搜索过去的对话
session_search(query="docker deployment", days=30)
```

---

### Honcho（用户建模）

Honcho 是一个外部 Memory Provider，提供更深层的用户建模：

- 知识图谱
- 语义搜索
- 自动事实提取
- 跨会话用户建模

```bash
hermes memory setup  # 选择并配置 Memory Provider
hermes memory status # 查看状态
```

## 第四步：知识关联

### 三个系统的关系

```
┌─────────────────┐
│   Session       │  ← 对话记录（自动存储）
│   Search        │
└─────────────────┘
        ↓
┌─────────────────┐
│   Memory        │  ← Agent 精选的重要信息
│   (MEMORY.md)   │     （手动管理）
└─────────────────┘
        ↓
┌─────────────────┐
│   Skills        │  ← Agent 创建的可复用流程
│   (SKILL.md)    │     （自动创建）
└─────────────────┘
```

| 系统 | 内容 | 管理 | Token 消耗 |
|------|------|------|------------|
| Session Search | 所有对话 | 自动 | 按需 |
| Memory | 精选信息 | Agent 手动 | 固定 ~1300 tokens |
| Skills | 可复用流程 | Agent 自动 | 按需加载 |

## 🎯 关键理解

1. **学习闭环是 Hermes 的核心差异**：其他 Agent 没有
2. **Memory 是精选的**：不是所有东西都记，有容量限制
3. **Skills 是自动创建的**：Agent 会在复杂任务后自动创建
4. **Session Search 是后盾**：Memory 记不住的，可以搜索过去对话
