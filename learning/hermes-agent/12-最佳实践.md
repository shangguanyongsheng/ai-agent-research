# 12-最佳实践

> Hermes Agent 的使用技巧、常见问题、故障排除指南。

---

## 第一步：概念解释

### 为什么需要最佳实践？

Hermes 是一个复杂的 Agent，有很多可配置选项。最佳实践帮助你：
- 避免 Token 浪费
- 提高响应速度
- 保持安全
- 优化成本

---

## 第二步：类比理解

### 最佳实践 = 使用手册的"高级技巧"

基础使用 → 按默认配置工作
最佳实践 → 调优后的高效使用方式

**类比：**

```
基础使用：
- 默认 Memory 配置
- 所有工具启用
- 不管理 Skills

最佳实践：
- 精选 Memory 内容
- 按场景启用工具
- 定期更新 Skills
→ 更高效、更省钱
```

## 第三步：代码/实践

### Token 优化

#### Memory 管理

```markdown
✅ 好的 Memory 条目（紧凑、信息密集）：
User runs macOS 14, Homebrew, Docker Desktop + Podman. Shell: zsh + oh-my-zsh. Editor: VS Code + Vim bindings.

❌ 坏的 Memory 条目（冗长）：
On January 5th, 2026, the user asked me to look at their project which is located at ~/code/api. I discovered...
```

#### 压缩策略

```bash
# 定期压缩上下文
/compress

# 或设置自动压缩阈值
# ~/.hermes/config.yaml
compression:
  enabled: true
  threshold_tokens: 100000
```

#### Skills 渐进式加载

```bash
# 不要一次性加载所有 Skills
# Agent 会按需要加载（Level 0 → Level 1）
```

### 安全最佳实践

#### 用户授权

```bash
# ✅ 使用允许列表
TELEGRAM_ALLOWED_USERS=123456789,987654321

# ❌ 不要开放所有人
GATEWAY_ALLOW_ALL_USERS=true  # 危险！
```

#### 终端隔离

```bash
# ✅ 使用 Docker/SSH 后端
hermes config set terminal.backend docker

# ❌ 生产环境不要用 local
hermes config set terminal.backend local  # Agent 可修改自己的代码
```

#### Command Allowlist

```yaml
# ~/.hermes/config.yaml
approval:
  allow_patterns:
    - "ls *"
    - "cat *.txt"
    - "docker ps"
  deny_patterns:
    - "rm -rf /"
    - "sudo *"
```

### 成本优化

#### Provider 选择

```bash
# ✅ 使用 OpenRouter 多模型路由（成本优化）
hermes model
# 选择 OpenRouter + 成本较低的模型

# ✅ 配置 fallback
# ~/.hermes/config.yaml
fallback_providers:
  - provider: openrouter
    model: hermes-3
```

#### Serverless 部署

```bash
# ✅ Terminal Backend 用 Modal/Daytona
hermes config set terminal.backend modal
# 空闲时不付费
```

#### Gateway 部署

```bash
# ✅ Gateway 在低成本 VPS ($5/月)
# Terminal 在 Serverless
# → 总成本接近 $5/月
```

### Memory 最佳实践

#### 记什么

```markdown
✅ 记：
- 用户偏好（语言/风格/工具）
- 环境信息（OS/Shell/已安装工具）
- 项目约定（语言/框架/CI）
- 纠正和教训（不要用 sudo，端口是 2222）
- 重要决定（已迁移数据库到 PostgreSQL）

❌ 不记：
- 太模糊的信息
- 可重新发现的事实
- 大段代码/日志
- Context Files 已有的内容
```

#### 容量管理

```python
# 当 Memory > 80% 时
# Agent 应合并条目

# 三个条目 → 一个条目
memory(action="replace", target="memory",
    old_text="Project uses Go",
    content="Project ~/code/api: Go 1.22, sqlc, chi router, GitHub Actions CI")
```

### Skills 最佳实践

#### 自动创建时机

```markdown
✅ 自动创建 Skill：
- 完成 5+ 工具调用的复杂任务
- 发现错误后找到正确路径
- 用户纠正后学到新流程
- 发现非平凡工作流

❌ 不创建 Skill：
- 简单的一次性任务
- 标准工具使用（不需要额外指导）
```

#### 使用 Skills Hub

```bash
# ✅ 安装前检查
hermes skills inspect openai/skills/k8s

# ✅ 使用 --force（已审查后）
hermes skills install openai/skills/k8s --force

# ✅ 定期更新
hermes skills check
hermes skills update
```

### Cron 最佳实践

#### Prompt 自包含

```markdown
✅ 好：
"SSH 到 192.168.1.100 作为 deploy，
执行 'systemctl status nginx'，
验证 https://example.com 返回 HTTP 200"

❌ 坏：
"检查服务器问题"  # 太模糊
```

#### 监控任务用 [SILENT]

```markdown
✅ 好：
Check nginx status. If healthy, respond [SILENT].
Otherwise report issue.

→ 正常时不打扰，异常时通知
```

#### 使用 Skills

```bash
# ✅ Skill-backed Cron
hermes cron create "every 1h" "Check feeds" --skill blogwatcher
# Skill 提供流程，Prompt 只需写任务
```

### 故障排除

#### 常见命令

```bash
hermes doctor        # 诊断问题
hermes config show   # 查看配置
hermes gateway status # Gateway 状态
journalctl --user -u hermes-gateway -f  # Gateway 日志
```

#### 常见问题

| 问题 | 解决 |
|------|------|
| **模型无响应** | 检查 API Key，用 `hermes model` 重新配置 |
| **Gateway 不启动** | 检查 `journalctl` 日志，用 `hermes doctor` |
| **Memory 太满** | Agent 合并条目，或删除不重要信息 |
| **Skills 加载失败** | 检查 SKILL.md 格式，用 `hermes skills list` |
| **Cron 不执行** | 检查 Gateway 是否运行，`hermes cron status` |
| **中断不生效** | 检查 Gateway 配置，确保收到新消息 |

## 🎯 关键理解

1. **Token 是成本**：紧凑 Memory，定期压缩
2. **安全是底线**：允许列表，终端隔离
3. **成本可优化**：Serverless Terminal
4. **Memory 要精选**：不是所有东西都记
5. **Skills 要审查**：Skills Hub 安装前检查
6. **Cron 要自包含**：Prompt 必须完整
