# 🟠 09 — 怎么写好 Prompt？（提示词工程）

> 💡 一句话：**写好 Prompt = 给 Agent 写一份清晰的工作手册。**

---

## 一个比喻

你雇了一个新员工，怎么让他快速上手？

给一份 **岗位说明书**：
- 👤 你是谁（角色）
- 📋 你做什么（职责）
- 🔧 你用什么（工具）
- 📝 你怎么汇报（格式）
- 🚫 你不能做什么（红线）

**系统提示词就是 Agent 的岗位说明书。**

---

## 好 Prompt 的五要素

```
👤 角色定义  → 你是谁
📋 任务描述  → 你做什么
🔧 工具说明  → 你用什么
📝 输出格式  → 你怎么汇报
🚫 安全约束  → 你不能做什么
```

## 好 vs 差 对比

| | ❌ 差 | ✅ 好 |
|--|-------|-------|
| **角色** | "你是一个 AI 助手" | "你是 Python 高级工程师，擅长数据处理和 API 开发" |
| **任务** | "帮我写代码" | "读取 CSV，按日期分组，计算每日销售总额，输出 JSON" |
| **格式** | （没有指定） | "用中文回复，代码用代码块，结果用表格" |
| **约束** | （没有指定） | "不要删除原始文件，不要访问 /etc 目录" |

## 写好 Prompt 的 5 个原则

1. **具体 > 模糊**："用 2 空格缩进"比"格式化代码"好 10 倍
2. **结构化 > 一大段**：用标题和列表，别写长段落
3. **少而精 > 大而全**：保持在 200 行以内，太长了 Agent 记不住
4. **可验证 > 主观**："输出 JSON 格式"比"好好整理"好
5. **有例子 > 纯描述**：给一个输入输出示例，胜过千言万语

## 一个完整示例

```markdown
# 角色
你是一个技术文档工程师，擅长把复杂技术写成小白能看懂的文章。

# 任务
把用户提供的技术文档重写成费曼学习法风格的教程。

# 工具
- read_file：读取原始文档
- write_file：写入重写后的文档

# 输出格式
- 用中文
- 开头用一句话总结
- 用生活类比
- 给出实际代码示例
- 最后用一句话总结

# 约束
- 不改变技术事实
- 不添加原文没有的内容
- 保持代码可运行
```

## 总结

> 好 Prompt = 好岗位说明书。写得越清楚，Agent 干得越漂亮。
