# 🟢 03 — Agent 怎么被管理？（Harness）

> 💡 一句话：**Harness 是 Agent 的方向盘、油门、刹车和仪表盘。**

---

## 一个比喻

你雇了一个超级能干的员工（Agent）。他很聪明，但——
- 他可能不知道公司的规矩
- 他可能乱删文件
- 他可能泄露机密
- 你可能不知道他在干什么

**Harness 就是管理这个员工的"经理系统"。**

---

## Harness 六大功能

| 功能 | 做什么 | 具体例子 |
|------|--------|---------|
| **🔧 工具管理** | 给 Agent 配工具 | 只能用授权的 API 和文件 |
| **📋 流程编排** | 定义做事顺序 | 先读→再分析→再出报告 |
| **🧠 状态管理** | 记住工作进度 | Agent 知道上一步做了什么 |
| **🚧 边界约束** | 限制行为范围 | 只能在工作目录操作 |
| **📊 监控调试** | 追踪决策过程 | 你能看到 Agent 的每一步思考 |
| **🛡️ 安全防护** | 防止危险操作 | 不能 `rm -rf /` |

## 有 Harness vs 没有 Harness

**没有 Harness：**
```
用户："帮我整理项目文件"
Agent：rm -rf /    😱 把系统删了
```

**有 Harness：**
```
用户："帮我整理项目文件"
Harness：检测到危险操作，拦截 ❌
Agent："我只会整理项目目录，不会碰系统文件。"
```

## 为什么 Harness 比 Agent 本身更重要？

> 一个没有 Harness 的 Agent，就像一辆没有刹车的跑车——跑得再快，也不敢上路。

Harness 确保 Agent：
1. ✅ **做对的事**（流程编排）
2. ✅ **正确地做事**（工具管理）
3. ✅ **不做危险的事**（安全防护）
4. ✅ **让你知道它在做什么**（监控调试）

## 总结

> Agent 决定"怎么做"，Harness 决定"能不能做"。
> 好的 Harness = 强能力 + 强约束。
