# 🟠 08 — Agent 的安全防护

> 💡 一句话：**给 Agent 设个围栏，让它在安全范围内发挥最大能力。**

---

## 一个比喻

你带小孩去游乐场。小孩很活泼，但你不会让他——
- 跑出游乐场大门
- 碰带电的设备
- 一个人玩到凌晨

**安全沙箱就是 Agent 的游乐场围栏。**

---

## 四大安全机制

| 机制 | 做什么 | 具体例子 |
|------|--------|---------|
| **🔍 代码审查** | 执行前检查危险操作 | 检测 `rm -rf`、`sudo` 等 |
| **⏱️ 执行超时** | 限制运行时间 | 30 秒没完成就强制终止 |
| **📦 资源限制** | 限制 CPU/内存/磁盘 | 防止 Agent 把服务器跑崩 |
| **🔐 权限控制** | 限制访问范围 | 只能访问工作目录 |

## 真实场景

```
用户："帮我清理不用的文件"

❌ 没有沙箱：
Agent：rm -rf /tmp/* && rm -rf ~/.cache/* && rm -rf /var/log/*
（可能删了不该删的）

✅ 有沙箱：
Harness：检测到操作范围超出工作目录 → 拒绝 ❌
Agent："我只能清理项目目录下的文件。"
```

## 安全 vs 能力的平衡

> 🔒 沙箱太严 → Agent 什么都做不了
> 🔓 沙箱太松 → Agent 可能搞破坏

好的安全策略：
1. **默认拒绝**：不在白名单的操作一律拒绝
2. **分级授权**：低风险自动执行，高风险需要确认
3. **审计追踪**：所有操作都有日志

## 总结

> 好的安全防护 = 让 Agent 在围栏内自由发挥，而不是把 Agent 绑起来。
