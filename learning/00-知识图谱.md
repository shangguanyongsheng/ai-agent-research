## 📚 一、基础概念

### 1.1 Agent 是什么？

**给小孩解释**：
> Agent 就像一个聪明的机器人助手。你告诉它想做什么，它会自己想办法完成任务。它能看文件、写代码、上网搜索，还能记住之前学过的东西。

**技术定义**：
> Agent = 感知 + 决策 + 行动 + 学习

| 组件 | 说明 | 类比 |
|------|------|------|
| 感知 | 理解用户输入和环境 | 眼睛、耳朵 |
| 决策 | 思考如何完成任务 | 大脑 |
| 行动 | 执行操作（读写文件、调用 API） | 手脚 |
| 学习 | 从经验中改进 | 成长 |

**与普通 LLM 的区别**：

| 维度 | 普通 LLM | Agent |
|------|----------|-------|
| 交互 | 单轮对话 | 多轮、多任务 |
| 记忆 | 无 | 持久化记忆 |
| 工具 | 不支持 | 支持多种工具 |
| 执行 | 仅生成文本 | 可执行实际操作 |

📖 详细文档：[Agent Harness 研究报告](../docs/Agent_Harness研究报告.md)

### 1.2 Agent Harness（控制层）

**给小孩解释**：
> 如果 Agent 是一辆自动驾驶汽车，Harness 就是方向盘、油门、刹车和仪表盘。它控制 Agent 的行为，防止它"撞车"。

**核心功能**：

```
┌─────────────────────────────────────────────┐
│            Agent Harness (控制层)            │
├─────────────────────────────────────────────┤
│  工具管理  │  流程编排  │  状态管理          │
│  边界约束  │  监控调试  │  安全防护          │
└─────────────────────────────────────────────┘
```

**为什么需要 Harness**：

| 问题 | Harness 解决方案 |
|------|-----------------|
| 无记忆 | 状态管理 + 持久化 |
| 无工具 | 工具绑定与管理 |
| 无规划 | 流程编排引擎 |
| 无边界 | 安全策略 + 权限控制 |

📖 详细文档：[Agent Harness 研究报告](../docs/Agent_Harness研究报告.md)

### 1.3 ReAct 框架

**给小孩解释**：
> ReAct 就像做题四步法：思考 → 写答案 → 检查 → 改错。如果错了，就重新思考再做一遍。

**核心循环**：

```
┌─────────────────────────────────────────────────────┐
│                   ReAct 循环                         │
│                                                     │
│   Thought（思考）→ Action（行动）→ Observation（观察）│
│                           ↑                         │
│                    失败了？反思后重试                  │
└─────────────────────────────────────────────────────┘
```

**示例**：

| 步骤 | 示例 |
|------|------|
| Thought | "用户想按授信类型分组" |
| Action | 执行分组代码 |
| Observation | 结果错误：列名拼写错误 |
| Reflection | "分组列名应该是 'credit_type' 不是 'credit'" |

📖 详细文档：[01-ReAct 框架](./01-react-framework.md)

### 1.4 记忆系统

**给小孩解释**：
> Agent 有两个"脑子"：一个是长期记忆（像日记本），一个是工作记忆（像便签纸）。长期记忆永远保存，工作记忆用完就扔。

**双记忆系统**：

```
长期记忆（持久化）          工作记忆（临时）
├─ 全局规则 BI_RULES.md    ├─ 当前会话上下文
├─ 用户记忆 users/         ├─ 错误日志
└─ 历史对话               └─ 纠正记录
```

| 记忆类型 | 存储位置 | 生命周期 |
|---------|---------|---------|
| 全局记忆 | BI_RULES.md | 永久 |
| 用户记忆 | users/{user_id}/ | 永久 |
| 工作记忆 | 内存 | 会话内 |

📖 详细文档：[02-记忆系统](./02-memory-system.md)

### 1.5 进化引擎

**给小孩解释**：
> Agent 会自己变聪明！每天分析犯过的错误，每个月总结出新的技能。就像学生每天做错题本，每月总结学习方法。

**螺旋上升**：

```
每日进化                     每月进化
├─ 收集日志                 ├─ 分析月度统计
├─ 分析错误模式             ├─ 生成新 Skill
├─ 低风险自动修复           └─ 通知决策者
└─ 记录改进
```

**触发条件**：

| 条件 | 阈值 | 动作 |
|------|------|------|
| 同类错误 | ≥3 次 | 记录模式 |
| 同一纠正 | ≥2 次 | 低风险修复 |
| 月度纠正 | ≥10 次 | 生成新 Skill |

📖 详细文档：[04-进化引擎](./04-evolution-engine.md)

## 🛠️ 二、工具平台

### 2.1 OpenClaw

**一句话介绍**：自托管的 AI Agent 网关，让 Agent 通过聊天应用（WhatsApp、Telegram、Discord）与你交互。

**核心能力**：

| 能力 | 说明 |
|------|------|
| 多渠道 | WhatsApp、Telegram、Discord、iMessage |
| 多模型 | 35+ 模型提供商 |
| 自动化 | Cron 定时任务、Heartbeat 检查 |
| 移动端 | iOS/Android 节点配对 |

**常用命令**：

```bash
# 检查状态
openclaw gateway status

# 打开控制面板
openclaw dashboard

# 安装技能
openclaw skills install <skill-name>
```

📖 详细文档：[OpenClaw 使用手册](../docs/OpenClaw使用手册.md)

---

### 2.2 Claude Code

**一句话介绍**：Anthropic 官方的命令行工具，让 Claude 在终端中自主完成开发任务。

**与 Cursor/Copilot 的区别**：

| 特性 | Claude Code | Cursor | Copilot |
|------|-------------|--------|---------|
| 模式 | 代理型（自主执行） | 辅助型 | 补全型 |
| 文件操作 | ✅ 自主读写 | ✅ 需确认 | ❌ |
| 命令执行 | ✅ 执行 Shell | ❌ | ❌ |
| 项目探索 | ✅ 自动分析 | ⚠️ 有限 | ❌ |

**常用命令**：

```bash
# 启动
claude

# 检查状态
claude /status

# 切换模型
claude /model claude-sonnet-4
```

📖 详细文档：[Claude Code 使用手册](../docs/Claude_Code使用手册.md)

### 2.3 Skills（技能）

**一句话介绍**：预定义的任务模板，让 Agent 具备特定领域的能力。

**技能类型**：

| 类型 | 位置 | 示例 |
|------|------|------|
| 内置技能 | 系统安装 | github, weather |
| 托管技能 | ~/.openclaw/skills/ | agent-reach |
| 工作空间技能 | workspace/skills/ | evomap-connector |

**安装技能**：

```bash
# 从 ClawHub 安装
npx skills add <owner/repo@skill>

# 或使用 OpenClaw CLI
openclaw skills install <skill-name>
```

📖 详细文档：[03-Skills 工具系统](./03-skills-system.md)

## 🌐 三、进阶主题

### 3.1 EvoMap 进化网络

**一句话介绍**：全球 AI Agent 共享知识的网络，让 Agent 能继承他人的能力。

**核心概念**：

| 概念 | 说明 | 比喻 |
|------|------|------|
| Gene | 可复用的策略模板 | 菜谱 |
| Capsule | 已验证的解决方案 | 做出来的菜 |
| GDI | 质量评分（0-100） | 米其林评分 |
| Credit | 网络积分 | 积分 |

**自然选择**：

```
高质量 Capsule → 更多曝光 → 更多复用 → GDI 更高 → 正循环 ✅
低质量 Capsule → 无人问津 → 逐渐淘汰 → 负循环 ❌
```

📖 详细文档：[EvoMap 学习笔记](./EvoMap学习笔记.md)

---

### 3.2 Multi-Agent 协作

**一句话介绍**：多个 Agent 分工协作，像团队一样完成复杂任务。

**协作模式**：

```
┌─────────────────────────────────────────────────┐
│                 主 Agent (Router)                │
│                  任务分发 + 结果汇总              │
└─────────────────────────────────────────────────┘
        │           │           │           │
        ▼           ▼           ▼           ▼
   ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐
   │PM-Agent │ │Dev-Agent│ │QA-Agent │ │Ops-Agent│
   │需求调研 │ │代码开发 │ │测试验证 │ │部署运维 │
   └─────────┘ └─────────┘ └─────────┘ └─────────┘
```

**Agent 角色定义**：

| Agent | 角色 | 职责 |
|-------|------|------|
| pm-agent | 产品经理 | 需求调研、PRD 编写 |
| dev-agent | 开发工程师 | 代码实现、功能开发 |
| qa-agent | 测试工程师 | 测试用例、质量报告 |
| ops-agent | 运维工程师 | CI/CD、部署、监控 |

📖 详细文档：[07-Multi-Agent 协作](./07-multi-agent-collaboration.md)

### 3.3 安全与沙箱

**一句话介绍**：防止 Agent 执行危险操作，保护系统和数据安全。

**安全机制**：

| 机制 | 说明 |
|------|------|
| 代码审查 | 执行前检查危险代码 |
| 执行超时 | 限制运行时间 |
| 资源限制 | CPU、内存、磁盘限制 |
| 权限控制 | 文件系统访问控制 |

📖 详细文档：[08-安全与沙箱](./08-safety-sandbox.md)

---

### 3.4 Prompt Engineering

**一句话介绍**：设计系统提示词，让 Agent 按预期行为。

**核心要素**：

```
系统提示词
├─ 角色定义：你是谁
├─ 任务描述：做什么
├─ 工具说明：怎么用
├─ 输出格式：怎么回答
└─ 安全约束：不能做什么
```

📖 详细文档：[09-Prompt Engineering](./09-prompt-engineering.md)
